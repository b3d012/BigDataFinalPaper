01

Problem

Edge and Industrial IoT systems expose sensors, gateways, and cyber-physical devices to scanning, denial-of-service traffic, spoofing, abnormal packet timing, and protocol misuse. A useful IDS must not only detect attacks, but also explain alerts, handle imbalance, monitor drift, and store evidence for analyst review.

Operational reality

Security teams need more than a binary yes-or-no score. They need a detection layer that can be defended in a review, traced back to feature evidence, and monitored when the traffic distribution changes.

Design goal

This prototype emphasizes reproducible evaluation, analyst-facing explanations, and careful decision thresholds so the system stays practical instead of merely accurate.

02

Project Overview

The pipeline starts with Edge-IIoT traffic, then branches into binary detection, attack subtype attribution, explainability, drift monitoring, and dashboarded evidence storage.

Dataset

Edge-IIoT traffic with a cleaned feature contract and deduplicated training view.

Main detector

Binary XGBoost normal vs attack classifier.

Second stage

XGBoost attack-subtype classifier for attack-only rows.

Imbalance handling

Training-only SMOTE cross-validation to reduce leakage.

Explainability

SHAP global importance and top-3 local alert explanations.

Monitoring

Isolation Forest anomaly override and ADWIN drift detection.

Adaptation

Validation-gated retraining as a guarded backup path.

Dashboard

MongoDB-backed Streamlit interface for artifacts, live windows, PCAP replay, SHAP, drift, retraining, robustness, and latency evidence.

  • Mean attack FNR: 0.025%
Threshold calibration
  • Holdout threshold: 0.5 to 0.13
  • Attack recall: 99.96%

  • Attack precision: 97.23%
Attack-subtype model

08

Explainability

SHAP is used both globally and locally. Global SHAP highlights the most important network features, while live alerts store exactly the top-3 local contributors when available.

Typical informative features

TCP acknowledgement, TCP sequence, TCP flags, TCP length, UDP stream, MQTT header flags, and ICMP checksum appear prominently in the explanation views.

Why it matters

The alert payloads are easier to audit when a prediction is paired with the features that most influenced it, especially in a security review or demo setting.

09

Drift, Retraining, and Robustness

The adaptive layer is intentionally cautious. It is built to detect change, not to replace the active model blindly.

Drift logic

ADWIN monitors live probability changes, and PSI-based drift analysis compares reference and target distributions.

Retraining policy

Retraining is guarded by validation gates so the active model only changes when the evidence supports it.

Robustness checks

The robustness report includes surrogate FGSM and PGD-style checks and should be read as prototype evidence, not final production hardening.

Honest framing

The project is presented as a carefully verified prototype with local replay and demo conditions rather than a finalized enterprise IDS deployment.
